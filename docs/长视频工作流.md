# 可插拔长视频工作流

## 1. 项目与 run

```text
projects/{id}_书名/
├── project.json                 # provider 唯一事实源
├── input/
│   ├── topic_request.md
│   ├── topic.json
│   ├── copy.json
│   ├── script.txt
│   ├── storyboard.json
│   └── candidates/{run_id}/     # 模型候选
├── workflow/runs/{run_id}/
│   ├── state.json               # provider 快照 + 阶段状态
│   ├── tasks/                   # Codex 交互任务包
│   └── image_tasks.json         # 临时、provider-neutral 图片任务
├── assets/scenes/
├── audio/voice/
└── output/
```

新项目先固定 provider：

```bash
PY=/Users/spring/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/bin/python3
$PY pipeline/workflow.py create --project 003 --llm codex --image imagegen
$PY pipeline/workflow.py init --project 003
```

`create` 只允许在没有活动 run 时修改 provider。run 创建后始终使用自己的快照。

## 2. 内容阶段

每一阶段都遵循同一循环：

```bash
$PY pipeline/workflow.py run <run_id> <topic|copy|script|storyboard>
$PY pipeline/workflow.py verify <run_id> <stage>
# 人工明确确认后：
$PY pipeline/workflow.py promote <run_id> <stage>
```

topic 需要先选择候选：

```bash
$PY pipeline/workflow.py select-topic <run_id> <candidate_id>
```

topic 提升时写正式 `topic.json`、更新书名/作者，并将 `{id}_新项目` 安全重命名为 `{id}_书名`。id 不变。

Codex provider 不调用 OpenAI API。`run` 会把上下文、契约和候选目标写入 `workflow/runs/{run_id}/tasks/{stage}.json`，状态变为 `awaiting_external`。`$video-maker-production` 读取该任务包、只写指定候选路径，然后执行统一 `verify`。DeepSeek provider 则直接调用 API 并写同一候选格式。

## 3. 图片阶段

正式 `storyboard.json` 只描述叙事语义。公共层把视觉风格、角色身份锚点、16:9、字幕安全区和无文字规则装配成临时 ImageTask：

```bash
$PY pipeline/workflow.py run <run_id> images
$PY pipeline/workflow.py verify <run_id> images
# 人工查看全部候选后：
$PY pipeline/workflow.py promote <run_id> images
```

ImageGen 进入 `awaiting_external`，skill 按 `image_tasks.json` 生成 PNG 到候选目录。万相直接调用 API。失败时只能重试当前 provider；不得从 ImageGen 自动切万相或反向切换。

正式图片路径统一为 `assets/scenes/{block_idx:02d}_{beat_idx}.png`。历史图片没有来源元数据时原样保留，不做伪造。

## 4. Azure、渲染与 QA

`script` 提升后 voice 与 storyboard 同时解锁，所以 Azure 配音可与分镜/图片分支并行：

```bash
$PY pipeline/workflow.py run <run_id> voice
$PY pipeline/workflow.py run <run_id> render
$PY pipeline/workflow.py run <run_id> qa
```

- Azure 音色来自 `project.json.providers.speech.voice`。
- 密钥/区域来自 `AZURE_SPEECH_KEY`、`AZURE_REGION` 或根 `.env`。
- 网络、429、5xx 错误在 Azure 内最多重试 3 次，退避 2/5/10 秒。
- 失败后状态为 `failed`，已完成的音频缓存与 run 保留；再次运行同一阶段恢复。
- 不存在 Piper、Edge、系统 TTS 或自动语音回退。

渲染只读取正式 `script.txt`、`storyboard.json`、`assets/scenes/` 和 Azure 缓存。图片缺失时公共层用程序化背景兜底，但不会调用其他图片模型。QA 使用 ffprobe 检查媒体规格，并执行完整解码。

## 5. 状态

统一状态为：`pending / awaiting_external / generated / verified / promoted / failed / blocked`。

- topic/copy/script/storyboard/images：`generated → verified → promoted`。
- voice/render/qa：运行成功后直接 `promoted`，不另设人工提升。
- 前置阶段未提升时保持 `blocked`。
- API 或外部生成失败标记 `failed`，可在同一 provider 内恢复。

随时检查：

```bash
$PY pipeline/workflow.py status <run_id>
```

## 6. 回归检查

```bash
$PY -m py_compile pipeline/*.py pipeline/providers/*.py
$PY -m unittest discover -s tests -v
$PY pipeline/build_long.py --project 001 --frames
$PY pipeline/build_long.py --project 002 --blocks 0,2,5 --no-tts
```

非连续块测试验证原块号到分镜/图片键的映射；抽帧用于字幕、缺图兜底与运镜检查。正式全片还需检查 1920×1080、音频响度、三段 BGM、SFX 与完整解码。
